## 2026-10-24 · v1.0.1 · 午夜调度、停用与提醒修复

- 需求：每天 00:00 的请求记录偶尔显示 23:59；停用后仍执行的反馈；推迟菜单偶发遮挡；补充开发交接记录。
- 已确认原因：旧调度仅按单调时钟结束提醒，未复核系统时间；两个时钟的毫秒差可使午夜请求提前。旧界面只显示到分钟。旧逻辑还会把正常提醒定时器的毫秒延迟加到执行时间上。
- 新发现：只读进程清单存在会话 0 与桌面会话 1 的 Evenfall；Windows 计划任务 Evenfall 正以当前用户运行同一 EXE。旧版使用 Local 会话内互斥量，无法阻止跨会话副本。两个调度器各自持有内存状态，桌面停用不能通知后台副本，后台还可能覆盖持久化状态。此条件与停用反馈相符，但旧日志没有进程／会话标识，不能追溯每条历史请求的具体来源。
- 未确认原因：原生推迟菜单遮挡的原始操作路径未复现，不能断言某个特定焦点事件是唯一原因。
- 修复：日历计划保留原时间；倒计时与系统时间同时到期才产生候选请求，提交前再验证存在性、启用状态、修订版本及暂停状态。提交授权只能消费一次，不依赖最多 100 条的日志缓存。启动、恢复、调时后的不足一分钟仍补足 60 秒，并记录原因。
- 单实例：改为数据目录 instance.lock 文件的零共享独占句柄，由 Windows 跨进程／会话／权限级别执行；取得锁失败或目录不可写时不启动调度。进程退出后由系统释放锁，留下的空文件不表示仍被占用。Python 验证进程持锁、应用阻断、释放后启动和目录失败阻断。
- 停用：清除该任务全部提醒和推迟项，持续停用直到手动开启；编辑草稿不得覆盖当前开关状态。新增带任务标识、时间和状态的开关记录。取消本次按该次计划日期处理，不增加 24 小时冷却：前一天 23:59 取消紧接着的 00:00，下一次为再下一天 00:00。
- 界面：10／30／60 分钟选项在同一置顶提醒卡片内展开，避开任务栏；空间不足时缩放卡片以完整容纳选项；支持 Tab／Enter／Esc；切换提醒组、取消、提交时收起，展开不停止计时。自动提醒不激活，只有主动点击展开选项时允许获取焦点。
- 日志：分别显示原计划、本次目标和实际请求时间（到秒），诊断数据保留毫秒；系统接口调用前采样实际请求时间。不改写旧记录，缺失的原计划标注“旧版未记录”。仍区分系统接受请求与真正完成关机。
- 兼容：读入 schemaVersion 1／2，保存为 2；旧版 1.0.0 不能直接读取 2。升级前先停止仍在运行旧版的 Windows 计划任务，再退出托盘旧版，确认所有旧进程退出后复制备份整个 `%LOCALAPPDATA%\Evenfall`；回退旧版时恢复该备份。原有原子替换备份只保证最近一份，不能代替独立升级备份。
- 开发过程中旧版 EXE 正在使用，未强制退出或覆盖，也未修改实际计划任务；本次产物放在 `dist/v1.0.1`。本机旧版的托盘副本和计划任务副本均须退出后替换，旧版不会遵守新版文件锁，发布不会自动升级已下载的软件。
- 验证命令：`cmake --build build -j 2`、`ctest --test-dir build --output-on-failure`、`python scripts/release.py --dist-dir dist/v1.0.1`、`python scripts/qa.py --exe dist/v1.0.1/Evenfall.exe`。验证通过后用 `--reuse-exe` 重新打包文档，保持已测 EXE 字节不变。
- 验证结果与 EXE 校验值：见下方最终验收，以及 [验证报告](QA-REPORT.md)。
- 提交：[v1.0.1 对应提交](https://github.com/honina0101-boop/Scheduled-shutdown/commit/v1.0.1)；交付：[v1.0.1 Release](https://github.com/honina0101-boop/Scheduled-shutdown/releases/tag/v1.0.1)。各下载文件 SHA-256 见该 Release 的 SHA256SUMS.txt。
- 实现依据：[Windows 内核对象命名空间](https://learn.microsoft.com/en-us/windows/win32/termserv/kernel-object-namespaces)说明 Local 对象属于各会话；[CreateFile](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)说明零共享限制持续到句柄关闭。
- 未验证：实际关机、Windows 11 真机、多物理显示器、真实登录启动及真实睡眠恢复；安全桌面不在普通窗口置顶保证范围内。切换外部应用后的实际交互与物理 DPI 检查仍须真机完成；离屏截图及窗口属性断言不等于这些真机验证。

## 2026-10-26 · 启动冲突排查与处理

- 现象：出现“无法独占任务数据目录”的启动提示。
- 原因：独立后台启动入口可能先启动程序并占用目录，之后的桌面启动被跨会话单实例保护拦截。旧版允许重复调度，所以未显示此提示。
- 处理方法：先备份额外计划任务的定义，再禁用并停止重复后台启动入口，保留软件登录自启动。保留目录独占保护，避免恢复双副本调度。
- 验证结果：正常启动、重复打开后复用主窗口均通过，未再被该对话框拦截；仅一个实例运行。详细本机证据与备份只保存在本地，不包含在仓库或下载包中。
- 版本与范围：软件仍为 v1.0.1，本次未改动程序代码或发布资产，无需重新下载。未测试重新登录后的自启动，未触发真实关机。
